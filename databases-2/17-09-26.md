## 🗂️ Topics Covered

### 1. 🏗️ Building Your Own Image

A stock image is fine until you need something that isn't in it — a text editor inside the
container, for instance. Then you build on top of it:

```dockerfile
FROM httpd

RUN apt update

RUN apt install -y nano
```

| Instruction | Meaning |
|---|---|
| `FROM httpd` | Start from the official Apache image |
| `RUN …` | Execute this **while building the image** |
| `-y` | Answer "yes" automatically — nobody's there to confirm |

And point compose at the dockerfile instead of a ready-made image:

```yaml
services:
  web:
    build:
      context: .
      dockerfile: dockerfile
    ports:
      - 9000:80
    volumes:
      - ./html:/usr/local/apache2/htdocs
```

`context: .` is the folder the build runs in; `dockerfile:` names the file.

> ⚠️ `RUN` happens at **build** time, not on every start. Change the dockerfile and you have to
> rebuild before it takes effect.

### 2. 🗄️ MariaDB and Adminer

The actual point of the course:

```yaml
  db:
    image: mariadb
    restart: always
    environment:
      MARIADB_ROOT_PASSWORD: example
    volumes:
      - ta24blearndb2dbdata:/var/lib/mysql
    ports:
      - 33061:3306

  adminer:
    image: adminer
    restart: always
    ports:
      - 8080:8080

volumes:
  ta24blearndb2dbdata:
```

**Piece by piece:**

- **`environment:`** — configuration handed to the container. The MariaDB image reads
  `MARIADB_ROOT_PASSWORD` on first start and creates the root account with it.
- **`restart: always`** — bring it back if it crashes or the machine reboots.
- **`ta24blearndb2dbdata:/var/lib/mysql`** — a **named volume**. Docker manages the storage;
  you just name it. `/var/lib/mysql` is where MariaDB keeps its data.
- **`volumes:` at the bottom** — named volumes must be declared as well as used.
- **`33061:3306`** — MariaDB listens on 3306 inside; publishing it as **33061** lets a desktop
  client on your machine connect. A non-standard host port avoids clashing with any local
  MySQL install.

**Why a named volume rather than a bind mount** (`./something:/var/lib/mysql`)? You never want
to browse or hand-edit raw database files — you only need them to **survive the container being
destroyed**. Without it, `docker compose down` throws the data away.

**Adminer** is a single-file database admin UI, reachable at `localhost:8080`. It needs no
configuration — it asks for server, user and password in the browser. **The server name is
`db`**: containers reach each other by service name on the network compose creates for them.

## ✅ Takeaways

1. **`FROM` + `RUN`** builds a custom image on top of an official one; `RUN` is build-time.
2. **A container's port is invisible to your machine until you publish it.**
3. **Named volume for data you only need to persist**, bind mount for files you edit.
4. **Declare named volumes twice** — where used and in the top-level `volumes:` block.
5. **Containers find each other by service name** — Adminer connects to `db`, not `localhost`.
6. **The image's Docker Hub page is the documentation.** Both links above are sections of it.
