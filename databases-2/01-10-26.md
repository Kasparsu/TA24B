### 1. 🗂️ Finishing the cinema database structure

The class worked on the task *Kinoprojekt / Cinema project: andmebaasi struktuur ja
diagramm*, due today: `project.sql` exported from DataGrip (or another tool) and a diagram
generated from it. The checks from last lesson still apply:

- every table has an `id`, and references use a column of the same type with a
  **foreign key**;
- `null` or `not null` and unique or not are deliberate choices;
- if two tables that belong together have no line between them on the diagram, the
  foreign key is missing.

### 2. 🧰 Next step: an ORM, migrations and fake data

The structure now has to run in a real backend. Instead of hand-written SQL, the tables
are described in code through an **ORM**: models plus **migrations** (or the ORM's schema
file), which build the same structure on any machine. A **seeder** then fills the tables
with demo data generated by a **Faker** library, so the database has realistic looking
rows to work with from day one.

## ✅ Takeaways

1. **The diagram is the check**: no line between tables means no foreign key.
2. **Migrations make the structure reproducible** from code, on any machine.
3. **Seed with Faker**, not by hand, and keep every foreign key pointing at a real row.
