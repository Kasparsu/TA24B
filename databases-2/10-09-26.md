## 🗂️ Topics Covered

### 1. 🐳 Why Docker, for a Database Course

You could install MariaDB directly. Docker is worth the detour anyway:

- **Try a database system, then delete it** — nothing left installed on your machine
- **Run several at once** without them fighting over ports or config
- **Deployment gets boring** — the server needs Docker and nothing else; pull the project and
  start it
- **No lock-in to a host.** Moving provider doesn't mean rediscovering what an old project
  needed

It also pays off well beyond this course, so it was going to come up in the back-end subject
regardless.

**Prerequisite:** Docker Desktop installed **and running** on Windows — not just installed.

### 2. 📄 The First `docker-compose.yml`

Instead of long `docker run` commands, the setup is described in a file:

```yaml
services:
  web:
    image: httpd
    ports:
      - 9000:80
    volumes:
      - ./html:/usr/local/apache2/htdocs
```

| Key | Meaning |
|---|---|
| `services:` | Each entry is one container |
| `web:` | A name you choose |
| `image: httpd` | The official Apache image from Docker Hub |
| `ports: - 9000:80` | **host:container** — port 80 inside is `localhost:9000` outside |
| `volumes: - ./html:/…/htdocs` | **host:container** — your local `html/` folder *is* the web root |

**The volume is the important idea.** The container is disposable; your files stay on your
machine. Edit `html/index.html`, refresh the browser, and it's there — no rebuild, no copying
anything in.

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>Document</title>
</head>
<body>
    Wow cool stuff!
</body>
</html>
```

> 📖 **Read the image's Docker Hub page** before using it. That's where you find out which
> paths matter (`/usr/local/apache2/htdocs` for `httpd`) and which environment variables it
> accepts.

## ✅ Takeaways

1. **Docker lets you try database systems without polluting your machine**, and makes
   deployment portable.
2. **Docker Desktop must be running**, not merely installed.
3. **`ports:` and `volumes:` are `host:container`.** Getting them the wrong way round is the
   classic first mistake.
4. **A bind mount makes the container use your local files** — edit and refresh, no rebuild.
5. **Read the image's Docker Hub page** for the paths and variables it expects.
