### 1. 🔀 Page data into the router

Each page still set its own `$title` and `$posts` at the top of the view. Those moved
into the `switch`, right before the view is included, so the views in `views/` only hold
markup:

```php
switch ($_SERVER['REQUEST_URI']) {
    case '/':
        $title = 'World';
        $posts = [ /* ... */ ];
        include __DIR__ . '/../views/index.php';
        break;
    case '/us':
        $posts = [ /* ... */ ];
        include __DIR__ . '/../views/us.php';
        break;
    default:
        echo 404;
}
```

There is no `us.php` file being served anymore, so the address does not need `.php`:
the case and the nav link both became `/us`.

### 2. 📦 Classes in `src/`, and `include` vs `require`

The `switch` was commented out and a `src/` folder created for classes. Convention: **one
class per file, file named exactly like the class**, starting with a capital letter
(`Router.php` holds `class Router`).

`new Router()` in `index.php` fails with *Class "Router" not found*: every PHP file is its
own program and knows nothing about other files until it loads them.

| Statement | If the file is missing | Loading it twice |
|---|---|---|
| `include` | warning, **script keeps running** | redeclaration error |
| `require` | **fatal error, script stops** | redeclaration error |
| `include_once` / `require_once` | same as above | skipped, no error |

Why stopping is the better outcome: imagine the script creates some temporary files, then
needs the class, then deletes the files. With `include` the class is missing, the script
crashes later at `new`, and the files are never cleaned up. With `require` it stops before
doing anything. A missing footer partial is survivable; a missing class is not, so
**classes are loaded with `require`**.

`include` and `require` are basically copy-paste, which is why loading a class file twice
redeclares the class. `require_once` remembers what it already loaded.

### 3. ⚙️ Autoloading

Requiring every class by hand in every file does not scale. PHP can call a function of
yours whenever it meets a class it does not know yet:

```php
spl_autoload_register(function ($class) {
    $class = substr($class, 4);
    $class = str_replace('\\', '/', $class);
    require_once __DIR__ . "/../src/$class.php";
});
```

The callback receives the class name as a string. Double quotes let `$class` go straight
into the path. Now any class in `src/` loads the first time it is used, and classes that
are never used are never loaded.

The two lines before `require_once` exist because of namespaces (next section):

- `substr($class, 4)` cuts off the first 4 characters, the root namespace `App\`.
- `str_replace('\\', '/', $class)` turns namespace separators into folder separators.
  Windows accepts both `\` and `/` in paths, Linux and macOS only `/`, so **always write
  `/`**. The backslash has to be written as `'\\'` because a single `\` escapes the
  next character.

In real projects you will almost never write an autoloader yourself. It comes for free,
more on that later.

![Autoload](https://api.memegen.link/images/success/Wrote_spl__autoload__register_once/Never_typed_require_again.png)

### 4. 🏷️ Namespaces and `use`

Two problems appear in bigger projects:

- Hundreds or thousands of classes do not belong in one folder.
- Code from other people has class names too. Your `Client` (a shop customer) and a
  library's `Client` (an HTTP or database client) cannot both exist without a way to tell
  them apart.

A **namespace** is that way. The root one here is `App` (for a package others use, often
your GitHub name plus the project name), and subfolders become sub-namespaces:

```php
<?php

namespace App\Controllers;

class PublicController {

}
```

`src/Router.php` and `src/DB.php` got `namespace App;`. The full name of the controller is
now `App\Controllers\PublicController`, which the autoloader turns into
`src/Controllers/PublicController.php`.

Writing the full name every time is tedious, so `use` imports it once per file. An alias
with `as` is possible too, but a name like `PC` hides what the class is, so use it only
when two imported classes share a name:

```php
use App\Controllers\PublicController as PC;
use App\Router;

$router = new Router();
$db = new App\DB();
$controller = new PC();
```

Inside the same namespace, classes refer to each other by the short name without `use`.

### 5. 🧭 The `Router` class and `routes.php`

What did the `switch` do? Look at the path, find the matching case, run some code. The
`Router` does the same with a list of routes:

```php
class Router {
    private static $routes = [];

    public static function addRoute($path, $action) {
        self::$routes[] = ['path' => $path, 'action' => $action];
    }

    public static function getRoutes(){
        return self::$routes;
    }

    public function __construct(private $path)
    {

    }

    public function match() {
        foreach(self::$routes as $route) {
            if($route['path'] === $this->path) {
                return $route;
            }
        }
        return false;
    }
}
```

- The route list is **static**: it belongs to the class, so routes can be registered
  before any `Router` object exists. Static methods use `self::`, not `$this`.
- `$routes[] = ...` pushes onto the end of the array.
- The constructor stores the requested path (constructor property promotion again).
- `match()` returns the first route whose path is the same, or `false`.

The routes went into their own file, `routes.php` in the project root. It is not a class
(so not in `src/`, lowercase name) and not public, and it is loaded by hand. Each action is
an anonymous function holding what used to be inside a `case`:

```php
Router::addRoute('/', function () {
    $title = 'World';
    $posts = [ /* ... */ ];
    include __DIR__ . '/views/index.php';
});
```

The include path lost its `/..`: `views/` is next to `routes.php`.

`public/index.php` shrank to:

```php
require __DIR__ . '/../routes.php';

$router = new Router($_SERVER['REQUEST_URI']);
$match = $router->match();
if($match) {
    call_user_func($match['action']);
} else {
    echo 404;
}
```

`call_user_func` runs a callback that is stored in a variable.

### 6. 🎮 Controllers

`routes.php` with a hundred routes full of page code would be the same long file again.
The code moved into methods of `PublicController`, one per page:

```php
class PublicController
{
    public function index()
    {
        $title = 'World';
        $posts = [ /* ... */ ];
        include __DIR__ . '/../../views/index.php';
    }

    public function us()
    {
        $posts = [ /* ... */ ];
        include __DIR__ . '/../../views/us.php';
    }
}
```

(Two folders back now: `src/Controllers/` to the project root.)

`routes.php` becomes a list you can read at a glance, which addresses exist and which
controller method answers each one:

```php
Router::addRoute('/', [PublicController::class, 'index']);

Router::addRoute('/us', [PublicController::class, 'us']);
```

`PublicController::class` is the fully qualified class name as a string,
`'App\Controllers\PublicController'`, without typing it out.

Passing that array to `call_user_func` failed: *non-static method cannot be called
statically*. The methods are normal ones, so the router has to make an object first. It
still accepts closures too:

```php
if(is_callable($match['action'])) {
    call_user_func($match['action']);
} else if (is_array($match['action'])){
    $class = $match['action'][0];
    $controller = new $class();
    $method = $match['action'][1];
    $controller->$method();
}
```

`new $class()` creates an object from a class name in a variable, `$controller->$method()`
calls a method whose name is in a variable. A real router would also check that the array
has two elements, that the class exists and that the method exists.

Later, pages that need a login could get an `AuthController`, posts a `PostController`,
and so on, so no single file grows forever.

## ✅ Takeaways

1. **One class per file, named like the class**, in `src/`.
2. **`require` for things the program cannot run without**; `_once` to load safely more than once.
3. **Autoloading** loads a class the first time it is used. Write `/` in paths, never `\`.
4. **Namespaces** follow folders and keep same-named classes apart; `use` shortens the names.
5. **`routes.php` is the map of the site**: path to controller method, nothing else.
6. **Controllers hold the page logic**, grouped by area, so no file grows forever.
