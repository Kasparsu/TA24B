### 1. 🐛 Fixing the login check

Testing register and login again with the hashed passwords showed that the right password
did not get in. The cause was in the condition from last time:

```php
if(!$user || password_verify($_POST['password'], $user->password)) {
```

The idea is "go back to the login form if there is no such user **or the password does not
verify**", but the `!` was missing, so it read "or the password **does** verify". The fix
is one character:

```php
if(!$user || !password_verify($_POST['password'], $user->password)) {
    return redirect('/login');
}
```

A reminder that a condition written as "when to reject" needs every part negated.

### 2. 📋 Task: users CRUD

A quick recap of what the admin side can do with posts: list them, view one, edit, delete
and create. The task (already in Teams, due by the end of the lesson) is to build the same
for **users**, mostly by copying the post code and swapping posts for users:

- a view page for one user. A real system never shows the password; here you may show the

- deleting a user;
- creating a user, which is basically the same as registering.

## ✅ Takeaways

1. **`!password_verify(...)`**: reject when the password does **not** verify.
2. **Test the unhappy path too**: a login that lets a wrong password in looks fine until
   you try the wrong one.
3. **Users CRUD** follows the posts CRUD: list, view, create, edit, delete, never showing a
   plain password and hashing a changed one.
