### 1. 🚀 Installing Laravel

Everything built in learnphp (router, controllers, models, migrations, auth) exists in
every framework, only more complete and more secure. Nobody writes a framework from
scratch for each project. The installation guide was shared in the chat:
<https://laravel.com/framework/docs/installation>.

The Laravel installer is a Composer package installed globally, so the `laravel` command
works in any folder:

```bash
composer global require laravel/installer
laravel new blog
```

`laravel new` asks a few questions. The **starter kit** decides the front end: React, Vue,
Svelte or Livewire, or none at all. Laravel is a full stack framework, so it can render
the HTML itself with its **Blade** templates, or serve a JavaScript front end. The class
chose no starter kit, so the project starts with plain Blade views. The installer also
ran the first migrations into an SQLite database file.

It also offered **Laravel Boost**, which writes guidelines and skills for AI coding agents
into the project (`AGENTS.md`, `CLAUDE.md`, `.agents/skills/...`) and registers an MCP
server for them:

```json
{
    "mcpServers": {
        "laravel-boost": {
            "command": "php",
            "args": [
                "artisan",
                "boost:mcp"
            ]
        }
    }
}
```

### 2. 🧩 VS Code and the Laravel extension

The project was opened in VS Code (trusting the folder). For Blade, routes and config
autocompletion it is worth installing the **Laravel Extension Pack**.

The project also ships an `.editorconfig`, which tells editors how to format files: UTF-8,
Unix line endings, indentation with 4 spaces (2 for YAML), a final newline:

```ini
[*]
charset = utf-8
end_of_line = lf
indent_size = 4
indent_style = space
insert_final_newline = true
trim_trailing_whitespace = true
```

### 3. 🗺️ A tour of the folders

From the top:

- **`app/`**: your own code, autoloaded under the `App` namespace (the same PSR-4 mapping
  as in learnphp). `Http/Controllers/` with a base `Controller`, `Models/` with a ready
  `User` model, and `Providers/` with `AppServiceProvider`.
- **`bootstrap/`**: starts the application. `bootstrap/app.php` wires up the routes,
  middleware and exception handling; you rarely touch it:

  ```php
  return Application::configure(basePath: dirname(__DIR__))
      ->withRouting(
          web: __DIR__.'/../routes/web.php',
          commands: __DIR__.'/../routes/console.php',
          health: '/up',
      )
  ```

- **`config/`**: one file per area (`app.php`, `database.php`, `mail.php`, ...). Most
  values are read from the environment, and Laravel has a `config()` helper to read them.
- **`database/`**: `migrations/` (users, cache and jobs tables already exist),
  `factories/` (fake data, e.g. `UserFactory`) and `seeders/` that use factories to fill
  the database, much like the seeding done in learnphp.
- **`public/`**: the web server's document root, with `index.php` (every request goes
  through it, like in learnphp), `robots.txt` and `favicon.ico`.
- **`resources/`**: `views/` (Blade templates such as `welcome.blade.php`), `css/` and
  `js/`.
- **`routes/`**: `web.php` for the pages and `console.php` for command line commands. The
  only route so far:

  ```php
  Route::get('/', function () {
      return view('welcome');
  });
  ```

- **`storage/`**: logs, cache, sessions and uploaded files.
- **`tests/`**: feature and unit tests.
- **`vendor/`**: Composer's packages, Laravel itself included. Never edit anything here;
  a `composer install` or `update` would overwrite it anyway.

### 4. 🔐 `.env` and `.env.example`

Settings that differ between computers, or that are secret, live in **environment
variables**. The operating system already has some (like `PATH`); Laravel reads its own
from the **`.env`** file in the project root:

```ini
APP_NAME=Laravel
APP_ENV=local
APP_KEY=
APP_DEBUG=true
APP_URL=http://localhost:8000

DB_CONNECTION=sqlite
# DB_HOST=127.0.0.1
# DB_PORT=3306
# DB_DATABASE=laravel
# DB_USERNAME=root
# DB_PASSWORD=
```

`APP_ENV` says whether this is local development or production, and further down are the
database connection, mail server and other credentials. Passwords must never end up on
GitHub, so `.env` is in the generated `.gitignore` together with `vendor` and
`node_modules`:

```
.env
.env.backup
.env.production
...
/node_modules
/vendor
```

What does get committed is **`.env.example`**: the same keys without real secrets, so
anyone cloning the project knows what to fill in.

### 5. ▶️ Running the app and the first commit

Laravel has front end tooling (Vite and Tailwind in `package.json`) next to the PHP side.
One command starts the development servers:

```bash
composer run dev
```

which runs `php artisan dev` from the `scripts` section of `composer.json`. The app opens
at <http://localhost:8000> with the Laravel welcome page. Finally a new `ta24bblog` repo
was created on GitHub and everything went in as the **first commit**.

## ✅ Takeaways

1. **Install once, use everywhere**: `composer global require laravel/installer`, then
   `laravel new <name>`.
2. **Starter kits** choose the front end; with none, Laravel renders Blade views itself.
3. **Your code lives in `app/`**, routes in `routes/`, views in `resources/views/`,
   migrations, factories and seeders in `database/`.
4. **`public/index.php` is the single entry point**, just like in learnphp.
5. **Never edit `vendor/`**: it belongs to Composer.
6. **`.env` holds secrets and stays out of git**; `.env.example` is the committed template.
7. **`composer run dev`** starts the app on <http://localhost:8000>.
