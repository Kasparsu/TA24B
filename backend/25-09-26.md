## 🗂️ Topics Covered

> 🧱 Last time the Bootstrap blog template landed in the project as one 700 line file. This
> session cut it into pieces, made a second page out of the pieces, and then moved
> everything behind a single entry point: the first router.

### 1. 🐚 A script for the server command

The development server command is easy to forget, so it went into a file:

```bash
# server.sh
php -S localhost:8000
```

Run it with `./server.sh` or `sh server.sh`. The `-S` has to be a capital S. With a small
`s` PHP tries to open `localhost:8000` as a file and fails.

### 2. 🧩 Cutting the template into partials

A **partial** is not a full page, just a part of one, hence the name. Each block of the
template was cut out (collapsing blocks in the editor helps to see where one ends) and
put back with an `include` at the exact spot it came from:

| Partial | What it holds |
|---|---|
| `header.php` | everything from `<!doctype html>` to the opening `<body>` |
| `icons.php` | the hidden SVG icon definitions (`display: none`, used elsewhere by reference) |
| `theme-select.php` | the light/dark/auto dropdown |
| `nav.php` | the top bar and the World, U.S., Technology ... links |
| `hero.php` | the big block at the top of the page, usually called the **hero** |
| `featured.php` | the two featured post cards |
| `posts.php` | the "From the Firehose" articles |
| `sidebar.php` | the sticky sidebar |
| `footer.php` | footer, scripts, closing tags |

The inline `<style>` block moved into `blog.css` along the way.

Icons, theme select and nav are needed on every page, so they are included from the end of
`header.php`, not from each page. What is left of `index.php` reads like a table of
contents:

```php
<?php include __DIR__ . '/partials/header.php'; ?>

<main class="container">
  <?php include __DIR__ . '/partials/hero.php'; ?>
  <?php include __DIR__ . '/partials/featured.php'; ?>

  <div class="row g-5">
    <div class="col-md-8">
      <?php include __DIR__ . '/partials/posts.php'; ?>
    </div>
    <div class="col-md-4">
      <?php include __DIR__ . '/partials/sidebar.php'; ?>
    </div>
  </div>
</main>
<?php include __DIR__ . '/partials/footer.php'; ?>
```

A student asked whether that many files for one page is overkill. Two reasons it is not:

- **Finding things.** "Change something in the sidebar" means opening `sidebar.php`, not
  scrolling through 700 lines.
- **More pages.** A second page reuses the same pieces. Fix the nav once and every page
  that includes it is fixed. With copied HTML files you would have to fix every copy, and
  with dozens of pages you will miss one.

![Partials](https://api.memegen.link/images/buzz/Partials/Partials_everywhere.png)

### 3. 📄 A second page, and posts from an array

`us.php` is a copy of `index.php` without the hero and the featured block. The nav links
changed from `#` to `/` and `/us.php`.

To make the pages differ in content, the posts became data: an array of associative arrays.

```php
$posts = [
  [
   'title' => 'Some World title 1',
   'date' => 'January 1, 2021',
   'author' => 'Pets',
   'body' => 'Some World body 1',
  ],
  // ... three more
];
```

`posts.php` keeps one `<article>` from the template and repeats it:

```php
<?php foreach($posts as $post): ?>
    <article class="blog-post">
        <h2 class="display-5 link-body-emphasis mb-1"><?= $post['title'] ?></h2>
        <p class="blog-post-meta">
            <?= $post['date'] ?> by <a href="#"><?= $post['author'] ?></a>
        </p>
        <p>
            <?= $post['body'] ?>
        </p>
    </article>
<?php endforeach; ?>
```

The editor marks `$posts` as undefined in `posts.php`. That is only because the tool does
not know which page will include it. The page that includes the partial must define it,
which is why `us.php` got its own U.S. posts.

### 4. ❓ Defaults: `isset`, the ternary and `??`

Each page also sets a `$title`. If a page forgets it, the `<title>` gets a PHP warning
printed inside it. Three ways to fall back to a default, all doing the same thing:

```php
// if(isset($title)) {
//   echo $title;
// } else {
//   echo 'Default title';
// }

// echo isset($title) ? $title : 'Default title';
// echo $title ?? 'Default title';
```

- **Shorthand if (ternary)**: `condition ? if_true : if_false`. Works for any condition,
  not only `isset`, and exists in most languages, JavaScript included.
- **Null coalescing operator `??`**: "this if it exists and is not null, otherwise that".
  Made exactly for the default value case.

The header now uses it:

```php
<title><?= $title ?? 'Blog' ?></title>
```

Warnings should stay on: they warn you about real problems. Fix the cause instead.

### 5. 🔓 Why serving the whole folder is a problem

Sites built like this still exist (legacy code), but **every file in the folder is
reachable from the browser**. `/README.md` opens. `/partials/posts.php` opens too, and
since `$posts` is not defined there, PHP prints a warning containing the full path of the
file. From that path an attacker learns:

- where the project lives on disk,
- the **username** (it is part of the path),
- the **operating system** (a `C:\` path means Windows).

Not a break-in by itself, but useful information for the next step of one. And having to
type `.php` at the end of every address is not nice either.

![Trap](https://api.memegen.link/images/ackbar/Opening_~spartials~sposts.php_directly/The_warning_shows_your_Windows_username.png)

### 6. 🚦 `public/` and a router script

The fix is the layout modern PHP projects use:

- `views/`: the pages and partials, **not** reachable directly.
- `public/`: the only folder the web server shows. Assets and `blog.css` go here.
- `public/index.php`: a new file (not the old homepage) that receives **every** request.

The server is started with `public` as the document root and `public/index.php` as the
router script:

```bash
php -S localhost:8000 -t public public/index.php
```

Now any address, `/`, `/asdf`, `/some/folder`, runs `public/index.php`. Which page the user
wanted is in the superglobal `$_SERVER`, under `REQUEST_URI` (URI, not URL).

`var_dump($_SERVER)` looks like one long line in the browser, because HTML ignores line
breaks. Two elements keep them: `<textarea>` and `<pre>` (preformatted text). That gave a
small helper:

```php
function dump(...$vars) {
    echo '<pre>';
    var_dump(...$vars);
    echo '</pre>';
}
```

The `...` appears twice with two jobs: in the parameter list it **collects** any number
of arguments into an array, in the call it **spreads** the array back out as separate
arguments (the PHP RFCs on argument unpacking and the spread operator, linked below).

The first router is a `switch` on the requested path:

```php
switch($_SERVER['REQUEST_URI']) {
    case '/':
        include __DIR__ . '/../views/index.php';
        break;
    case '/us.php':
        include __DIR__ . '/../views/us.php';
        break;
    default:
        echo 404;
}
```

`echo 404` is a placeholder, a proper 404 comes later. For a fun error page there is a cat
for every HTTP status code: <https://http.cat/>.

**CSS and JS broke**, because the request for `blog.css` also ran `index.php`. The PHP
manual's built-in web server page has the answer: if the router script returns `false`,
the server sends the requested file as it is. The pattern got `js` and `css` added:

```php
if (preg_match('/\.(?:png|jpg|jpeg|gif|js|css)$/', $_SERVER["REQUEST_URI"])) {
    return false;    // serve the requested resource as-is.
}
```

`preg_match` is a regular expression, a pattern language that exists in every language.
This one matches paths ending in an image, JS or CSS extension. It still answered "not
found" until `-t public` made `public/` the root, so the server looks for `blog.css` in
the right folder.

![Router](https://api.memegen.link/images/morpheus/What_if_I_told_you/every_URL_runs_public~sindex.php.png)

A `switch` with every page in one file will not scale. A better router comes next time.

## ✅ Takeaways

1. **Put long commands in a script** (`server.sh`).
2. **Partials** make pages short to read and let many pages share one nav, header and footer.
3. **Data in arrays, markup in a loop**: the page that includes a partial supplies its variables.
4. **`$x ?? 'default'`** for defaults; the ternary for any other two-way choice.
5. **Only `public/` should be reachable.** Everything else can leak paths, usernames and the OS.
6. **One entry point**: every request runs `public/index.php`, which reads `REQUEST_URI` and
   decides what to show. Static files are let through with `return false`.
