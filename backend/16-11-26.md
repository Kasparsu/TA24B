### 2. 📦 Installing Composer

JavaScript has npm (and Bun, which still downloads from the npm registry). PHP's package
and dependency manager is **Composer**: <https://getcomposer.org/download/>. On Linux and
Mac the installer is downloaded and run with PHP; on Windows there is also a setup file,
which mostly needs to find your PHP. Composer itself is a single PHP file.

After installing, **open a new terminal tab** (the new command is not known in the old one)
and check it with:

```bash
composer --version
```

It prints Composer's version and the PHP it found.

### 3. 🏗️ `composer init`

Run in the learnphp project folder, `composer init` is the counterpart of `npm init`, but
without a `-y` to accept all defaults, so it asks questions:

- **Package name**: guessed from your user name and the folder. It matters only for
  packages you publish (then usually `vendor/package`, vendor being your user or company
  name). Enter is fine.
- **Description, author, minimum stability**: optional; the author is taken from your git
  `user.name` and `user.email`.
- **Package type**: `project` (it is not a library, meta package or Composer plugin).
- **License**: empty keeps full copyright; an open source license allows others to use the
  code. The example used the WTFPL, the teacher's favourite (look it up).
- **Dependencies** (`require`) and **dev dependencies** (`require-dev`): the first are
  needed in production, the second only while developing (tests, fake data for seeding).
  None for now.
- **PSR-4 autoload**: it offers to map `src/`, which is right, but with its own namespace.
- **Add `vendor` to `.gitignore`**: yes. There was no `.gitignore` yet, so it creates one.

Like `node_modules`, `vendor/` is not your code, can be large and can always be recreated
with one command, so it stays out of git:

```
/vendor/
```

### 4. 🔁 Composer's autoloader instead of ours

`composer init` wrote `composer.json` (the counterpart of `package.json`) and generated an
autoloader in `vendor/`. The project's classes use the `App` namespace, so the mapping was
changed to that:

```json
"autoload": {
    "psr-4": {
        "App\\": "src/"
    }
},
```

The generated files still have the old namespace, so they are rebuilt with:

```bash
composer dump-autoload
```

Back in the first lessons `public/index.php` got an `spl_autoload_register()` that "you
will never have to write yourself". This is why. It is replaced by one line:

```php
require __DIR__ . '/../vendor/autoload.php';
```

and every page still works.

### 5. 📏 PSR: PHP Standards Recommendations

Why could the autoloader be swapped without touching a single class? Because ours followed
**PSR-4**. **PSR** stands for **PHP Standards Recommendation**: rules the PHP community
agreed on so that everyone writes and organises code the same way. Many open and closed
source projects use them, and an open source project can simply say "we follow PSR, pull
requests that do not are not accepted". The ones to read:

- **PSR-1**, basic coding standard (<https://www.php-fig.org/psr/psr-1/>): which PHP tags
  to use, namespaces and classes follow autoloading, class names in `StudlyCaps`, method
  names in `camelCase`;
- **PSR-4**, autoloading (<https://www.php-fig.org/psr/psr-4/>): how a namespace and class
  name map to a folder and file, which is exactly what our autoloader and Composer's do;
- **PSR-12**, extended coding style (<https://www.php-fig.org/psr/psr-12/>).

These conventions have been used in class from day one; now they have a name.

### 6. 🧰 Packagist and `symfony/var-dumper`

Where npm has npmjs.com, Composer has **Packagist** (<https://packagist.org/>).
(packagist.com is the paid private version for companies hosting their own packages.)
There are dozens of routers better than the one built in class, templating languages that
replace the PHP tags in HTML, whole frameworks, PDF, spreadsheet and image libraries.

The first package was a simple one that does something learnphp already does, only better:
**`symfony/var-dumper`** (<https://packagist.org/packages/symfony/var-dumper>). Its page
shows the install command, best copied rather than typed:

```bash
composer require symfony/var-dumper
```

`composer require` adds a new package (`composer install` installs what is already listed).
It wrote the package into `composer.json`:

```json
"require": {
    "symfony/var-dumper": "^8.1"
}
```

and created **`composer.lock`**, the counterpart of `package-lock.json`: it records the
exact versions downloaded, so a later install gets the same ones instead of silently
upgrading.

var-dumper adds two global functions, `dump()` and `dd()`, the same names as the helpers
written in class. Ours had to go, so both were deleted from `helpers.php` (they are still in
the git history). To see the difference the home page dumps its posts:

```php
$posts = Post::all();
$title = 'World';
dump($posts);
```

The output is dark themed, coloured, and objects and arrays can be collapsed and expanded,
much easier to read than `var_dump()` in a `<pre>`.

### 7. 📥 `composer install` after cloning

Because `vendor/` is not in git, a fresh clone does not have it, and the first run fails
with a warning that `vendor/autoload.php` cannot be found. Worth recognising, because the
fix is always the same:

```bash
composer install
```

It downloads the packages listed in `composer.lock` and regenerates the autoloader, just
like `npm install` or `bun install` after cloning a JavaScript project.

## ✅ Takeaways

1. **Composer is PHP's npm**: `composer.json` is `package.json`, `composer.lock` is
   `package-lock.json`, `vendor/` is `node_modules/`.
2. **Open a new terminal after installing** and check with `composer --version`.
3. **`vendor/` goes in `.gitignore`**; after cloning, `composer install` brings it back.
4. **Composer's autoloader replaces ours**: map the namespace in `composer.json`, run
   `composer dump-autoload`, require `vendor/autoload.php`.
5. **PSR-1, PSR-4 and PSR-12** are the shared PHP conventions; following PSR-4 is what made
   the swap painless.
6. **Find packages on Packagist** and add them with `composer require vendor/package`.
7. **`symfony/var-dumper`** gives a far nicer `dump()` and `dd()`, so our own versions were
   removed.
