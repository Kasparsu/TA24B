### 2. 🧪 `dd()`: dump and die

`dump()` already printed variables in a readable `<pre>` block, but the page kept running
afterwards, so the dump could end up buried under the rest of the HTML (or followed by a
redirect). A second helper does the dump and then stops the script right there:

```php
function dd(...$vars) {
    dump(...$vars);
    die;
}
```

`...$vars` takes any number of arguments, and `dump(...$vars)` spreads them back out. The
name comes from Laravel, where `dd()` is the everyday debugging tool. It is handy for
looking at what a form actually sent, before writing the code that uses it.

![dd](https://api.memegen.link/images/leo/dump()_and_die/in_one_helper:_dd().png)

### 3. 📝 The create form

Creating a post takes two requests: one to **show** the empty form, one to **receive** the
filled form. Each gets its own route and controller action:

```php
Route::get('/admin/posts', [PostController::class, 'index']);
Route::get('/admin/posts/create', [PostController::class, 'create']);
Route::post('/admin/posts', [PostController::class, 'store']);
```

Note that the list and the store share the same address, `/admin/posts`. The router tells
them apart by the method: a `GET` lists the posts, a `POST` adds one to the list. The
**New Post** button now points to the form:

```php
<a href="/admin/posts/create" class="btn btn-primary">New Post</a>
```

The `create()` action only shows a view:

```php
public function create() {
    view('posts/create');
}
```

(The view names now use a forward slash, `posts/index`, instead of a backslash. A forward
slash works as a path separator on every operating system, a backslash only on Windows.)

The form itself was built from Bootstrap's form control example
(<https://getbootstrap.com/docs/5.3/forms/form-control/#example>): a `mb-3` block per
field, a `label` with `form-label`, and the input with `form-control`. The post has two
fields, so there is a text input for the title and a `textarea` for the content:

```php
<form action="/admin/posts" method="POST">
    <div class="mb-3">
        <label for="title" class="form-label">Title</label>
        <input name="title" type="text" class="form-control" id="title" placeholder="Some title">
    </div>
    <div class="mb-3">
        <label for="body" class="form-label">Content</label>
        <textarea name="body" class="form-control" id="body" rows="3"></textarea>
    </div>
    <button class="btn btn-primary">Create</button>
</form>
```

Three things that Bootstrap's example does not have, but a working form needs:

- the **`<form>`** tag itself, with **`action`** (where to send it) and **`method="POST"`**;
- a **`name`** on every field. The `id` is only for the `label`; it is the `name` that
  becomes the key in `$_POST`. A field without a name is simply not sent;
- a **button** inside the form. A `button` in a form submits it by default.

### 4. 📬 Receiving the form: `store()`

The `store()` action makes a new, empty `Post` object, fills it from `$_POST` (keys are the
`name`s from the form) and asks it to save itself:

```php
public function store() {
    $post = new Post();
    $post->title = $_POST['title'];
    $post->body = $_POST['body'];
    $post->save();
    header('Location: /admin/posts');
}
```

The last line is a **redirect**. Instead of showing a page of its own, the server answers
with a `Location` header, and the browser goes there with a new `GET` request, so after
saving you land back on the table of posts and see the new row. It also means that
refreshing the page afterwards does not send the form a second time.

![POST at home](https://api.memegen.link/images/home/Can_we_have_Laravel_forms~q/We_have_$__POST_at_home.png)

### 5. 🏛️ `save()` in the `Model` base class

`save()` is not written in `Post`, but in the abstract `Model` from last time, so every
model gets it. The trick is **`get_object_vars($this)`**: it returns the object's
properties as an array, property names as keys. Since a model's properties are named
exactly like the table's columns, that array is already "column => value":

```php
public function save() {
    $db = new DB();
    $fields = get_object_vars($this);
    unset($fields['id'], $fields['created_at'], $fields['updated_at']);
    $db->insert(static::$table, $fields);
}
```

Three columns are removed with `unset()` before inserting, because the **database fills
them itself**: `id` is auto increment, and `created_at` and `updated_at` get the current
time by default. What remains for a post is `title` and `body`. `static::$table` again
picks the table of whichever model `save()` was called on.

![Philosoraptor](https://api.memegen.link/images/philosoraptor/If_the_model_already_knows_its_columns/why_would_I_write_the_INSERT_by_hand~q.png)

### 6. 🧩 `DB::insert()`: building the query

The `INSERT` syntax came from W3Schools
(<https://www.w3schools.com/php/php_mysql_insert.asp>):

```sql
INSERT INTO table (column1, column2) VALUES ('value1', 'value2')
```

`insert()` builds exactly that text from the table name and the fields array:

```php
public function insert($table, $fields) {
    $fieldNames = array_keys($fields);
    $fieldNamesText = implode(', ', $fieldNames);
    $fieldValuesText = implode("', '", $fields);
    $sql = "INSERT INTO $table ($fieldNamesText)
            VALUES ('$fieldValuesText')";
    $this->conn->exec($sql);
}
```

- **`array_keys()`** gives the column names, `['title', 'body']`.
- **`implode()`** glues an array into one string with a separator between the items:
  `', '` gives `title, body`.
- For the values the separator is `"', '"` (quote, comma, space, quote), and the query
  adds the first and last quote itself, so every value ends up in quotes:
  `'My title', 'My text'`.
- **`exec()`** runs a query that returns no rows, unlike `query()`, which `all()` uses
  for the `SELECT`.

Because nothing in it is about posts, the same method will insert users or any other
model. One thing to keep in mind about this first version: the values are pasted
straight into the SQL text, so a title with an apostrophe in it (`Kaspar's post`) breaks
the query. Values that come from a form need to be passed to the database separately
from the query, which is a topic for a later lesson.

## ✅ Takeaways

1. **PhpStorm and DataGrip are free for students**: apply with your school e-mail.
2. **`dd()` dumps and stops the script**, which makes it easy to see what a form sent.
3. **Creating takes two routes**: `GET /admin/posts/create` shows the form, `POST
   /admin/posts` receives it. The same address can do different things for different
   methods.
4. **A form needs `action`, `method="POST"` and a `name` on every field**; the `name` is
   the key in `$_POST`.
5. **Redirect after saving** with `header('Location: ...')`, so the browser loads the
   list again and a refresh does not resend the form.
6. **`get_object_vars($this)`** turns a model into a "column => value" array, so one
   `save()` in `Model` works for every model. Leave out the columns the database fills
   itself (`id`, `created_at`, `updated_at`).
7. **`array_keys()` and `implode()`** build the column and value lists of an `INSERT`;
   **`exec()`** runs a query that returns no rows.
8. **Pasting form values into SQL is fragile** (an apostrophe breaks it); a safer way
   comes later.
