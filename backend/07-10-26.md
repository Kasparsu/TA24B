### 1. 🤔 The problem: routes ignore the method

After Monday's form, `/answer` worked as a POST target, but typing `/answer` into the
address bar (a GET request) worked too. Two problems with that:

- A route cannot say which kind of request it is meant for.
- One address cannot do different things for different methods. With only GET and POST
  that sounds minor, but REST APIs also use PUT, PATCH, DELETE and others on the same
  address, and having to invent and remember a separate address for every action gets old
  fast.

So a route needs a third piece of information: the method.

### 2. 🧱 A `Route` class

The method could just be added to the associative array each route was stored as, but
checking that every array has the right keys gets annoying. A small class holds one route
instead:

```php
namespace App;

class Route {
    public function __construct(private string $method, private string $path, private $action)
    {

    }

    public function getMethod(){
        return $this->method;
    }

    public function getPath(){
        return $this->path;
    }

    public function getAction(){
        return $this->action;
    }
```

- The properties are **private**: set once when the route is created, never changed from
  outside. We do not need to change them, so that is exactly right.
- Private also means they cannot be *read* from outside, hence the **getters**. This
  getter style works in every PHP version back to the old ones; newer versions have
  shorter ways to write the same idea.
- `$action` has **no type**. `callable|array` was rejected: PHP does not allow `callable`
  as a property type. Parameters may use it, so the check moves to the methods that
  receive the action:

```php
public static function addRoute(string $method, string $path, callable|array $action) {
    self::$routes[] = new Route($method, $path, $action);
}
```

The router stores `Route` objects now, not arrays.

### 3. 🔀 Matching path *and* method

The `Router` constructor also receives the method the visitor used, and `match()` requires
both to agree:

```php
public function __construct(private $path, private $method)
{
    $this->path = parse_url($this->path, PHP_URL_PATH);
}

public function match() {
    foreach(self::$routes as $route) {
        if($route->getPath() === $this->path && $route->getMethod() === $this->method) {
            return $route;
        }
    }
    return false;
}
```

Each comparison gives a boolean, and the logical operators combine them:

- **`&&`** (and): true only if both sides are true
- **`||`** (or): true if either side is true
- **`!`** (not): flips true to false and back

PHP also accepts the words `and` and `or`, but almost nobody writes them: most languages
only have the symbols, and the symbols are shorter.

The request method comes from the same superglobal as the path:

```php
$router = new Router($_SERVER['REQUEST_URI'], $_SERVER['REQUEST_METHOD']);
```

`match()` now returns a `Route`, so `index.php` changes from array keys to getters:

```php
$class = $match->getAction()[0];
$controller = new $class();
$method = $match->getAction()[1];
$controller->$method();
```

`getAction()[0]` looks odd at first: call the method, then take element `0` of the array
it returns.

### 4. 🪄 `Route::get()` and `Route::post()`

Now every `addRoute` call in `routes.php` needs the method as a string, which is repetitive
and easy to mistype. Since there are only two methods to support, the `Route` class got
two convenience functions:

```php
public static function get(string $path, callable|array $action) {
    Router::addRoute('GET', $path, $action);
}
public static function post(string $path, callable|array $action) {
    Router::addRoute('POST', $path, $action);
}
```

The method names are **uppercase** because that is how `$_SERVER['REQUEST_METHOD']` gives
them. (Converting both sides to one case would also work, but with these functions nobody
types the string anyway.) The route file now says which method each address is for:

```php
Route::get('/forms', [PublicController::class, 'forms']);
Route::post('/answer', [PublicController::class, 'answer']);
```

Opening `/answer` in the address bar now gives a **404**: there is no GET route for it.
Submitting the form still works.

### 5. 🎭 Same address, different action

With the method in the match, `/answer` is no longer needed. The form can post to its own
address:

```php
Route::get('/forms', [PublicController::class, 'forms']);
Route::post('/forms', [PublicController::class, 'answer']);
```

```html
<form action="/forms" method="POST">
```

GET `/forms` shows the form, POST `/forms` runs `answer()`. Same address, two actions.

![Same address](https://api.memegen.link/images/glasses/One_~sforms_address/GET_shows_the_form,_POST_handles_it.png)

### 6. ⏪ Why Back showed the old form

While testing, the label was changed, then **Back** pressed, and the change was not there.
Back usually does not ask the server for the page again; the browser shows the HTML it
already has, to save bandwidth. For normal browsing that is what you want 99% of the time.

While developing it is a trap: change the form's `action`, press Back, submit, and the
*old* form is what gets sent, so it looks like your change did nothing. After going back,
**refresh**.

![Back button](https://api.memegen.link/images/scc/The_Back_button_never_asked_the_server/That's_why_my_change_wasn't_there.png)

### 7. 🔥 `git fire`

The end of the lesson was about leaving the building in case of fire, which led to a joke
that is only half a joke: **`git fire`**. It is not a built-in Git command, but ready-made
versions exist (or you can write your own alias or script). The idea: one command that
commits everything, checks out a new branch (often named with your name and the date),
and pushes it. Then you leave.

Why bother when you could grab a laptop? A desktop PC does not come with you, and a laptop
might not survive the trip either. Fire destroys an SSD just as well as an old spinning
disk. Code that only exists on your machine is code you can lose; a pushed emergency
branch can be pulled on any other computer and fixed later.

## ✅ Takeaways

1. **A route is a method, a path and an action.** The router matches both method and path.
2. **Private properties plus getters**: set once in the constructor, readable, never changed.
3. **`callable` cannot be a property type**, but it can type a parameter.
4. **`&&`, `||` and `!`** combine and flip booleans.
5. **`Route::get()` and `Route::post()`** say the method in the route file without typing strings.
6. **One address, two methods**: GET shows the form, POST handles it.
7. **Back does not reload. Refresh after changing a page**, and push your work before you leave.
