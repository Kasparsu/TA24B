### 1. 🌬️ Laravel Breeze: login and registration

Laravel has several **starter kits** for authentication. The simple one, with plain Blade
views, is **Breeze** (installation guide shared in the chat:
<https://laravel.com/framework/docs/11.x/starter-kits#laravel-breeze-installation>). It is
a development package that generates code into the project:

```bash
composer require laravel/breeze --dev
php artisan breeze:install
```

The installer asks for the stack (Blade) and a test framework (Pest). `composer.json` now
has:

```json
    "require-dev": {
        "fakerphp/faker": "^1.23",
        "laravel/boost": "^2.2",
        "laravel/breeze": "^2.4",
```

What Breeze generated is a big pile of code: controllers under `app/Http/Controllers/Auth/`
(login, registration, password reset, email verification), a `ProfileController`, form
request classes, Blade views for every auth page, layouts, small Blade components
(`primary-button`, `text-input`, `dropdown`, `modal` and others) and tests. All of its routes
go into a separate `routes/auth.php`, which `web.php` pulls in at the end:

```php
Route::get('/dashboard', function () {
    return view('dashboard');
})->middleware(['auth', 'verified'])->name('dashboard');

Route::middleware('auth')->group(function () {
    Route::get('/profile', [ProfileController::class, 'edit'])->name('profile.edit');
    Route::patch('/profile', [ProfileController::class, 'update'])->name('profile.update');
    Route::delete('/profile', [ProfileController::class, 'destroy'])->name('profile.destroy');
});

require __DIR__.'/auth.php';
```

Inside `auth.php` the `guest` group holds the pages for visitors who are not logged in:

```php
Route::middleware('guest')->group(function () {
    Route::get('register', [RegisteredUserController::class, 'create'])
        ->name('register');

    Route::post('register', [RegisteredUserController::class, 'store']);

    Route::get('login', [AuthenticatedSessionController::class, 'create'])
        ->name('login');
```

Breeze's views use **Alpine.js** for dropdowns and the mobile menu, so `alpinejs` was added
to `package.json` and started in `resources/js/app.js`:

```js
import Alpine from 'alpinejs';

window.Alpine = Alpine;

Alpine.start();
```

Of Breeze's front end changes, that is the only one in the commit: the project's Tailwind
setup stayed as it was. With the server running, the **Log in** and **Register** pages
work, and so do the dashboard and the profile page behind them.

### 2. 🧭 `PublicController` and a shared layout

The `/` route was still a closure in `web.php`. Our own pages get a controller, the same idea
as in learnphp:

```php
class PublicController extends Controller
{
    public function index() {
        return view('welcome');
    }

    public function buttons() {
        return view('buttons');
    }
}
```

```php
Route::get('/', [PublicController::class, 'index']);
Route::get('/buttons', [PublicController::class, 'buttons']);
```

Laravel's big default welcome page (over 200 lines) was replaced. Both pages now extend one
layout, `resources/views/partials/layout.blade.php`, which has the HTML skeleton and links
between the pages, and `@yield('content')` where each page puts its own part:

```blade
<body>
    <a href="/">home</a>
    <a href="/buttons">buttons</a>
    @yield('content')
</body>
```

```blade
@extends('partials.layout')
@section('content')
    <button>Button</button>
@endsection
```

### 3. 🎨 Tailwind: no ready made button

Bootstrap gives you components: write `btn btn-primary` and you have a styled button.
Tailwind works differently. It has no buttons or components, only small **utility classes**,
roughly one per CSS property, and you build the look out of them yourself.

The classes do nothing until the page loads the built CSS. Vite gives the built files
generated names, so the layout names the source files and Laravel finds the rest:

```blade
    @vite(['resources/css/app.css', 'resources/js/app.js']);
```

(The stray `;` at the end is not needed: it shows up as text on the page.) Then the first
Tailwind class on the button:

```blade
    <button class="bg-blue-400">Button</button>
```

A background colour is only the start. A proper button also needs rounded corners, padding,
a font size, and its **states**: hover, active (pressed) and focus (the ring when you reach
it with Tab). The browser's developer tools can force an element into such a state, so you
can inspect the styles without holding the mouse on it.

## ✅ Takeaways

1. **Breeze** is the simple Blade starter kit: `composer require laravel/breeze --dev`, then
   `php artisan breeze:install`.
2. **It generates code into your project**: auth controllers, views, components, tests, and
   its routes in `routes/auth.php`.
3. **Alpine.js** powers Breeze's dropdowns and menu.
4. **Own pages get a controller**: `PublicController` with `index` and `buttons`.
5. **A shared layout** with `@extends`, `@section` and `@yield` keeps the HTML skeleton in one
   place.
6. **`@vite`** loads the built CSS and JS; without it Tailwind classes do nothing.
7. **Tailwind has no components**, only utility classes: a good button needs many of them,
   states included.
