### 1. ↩️ A `redirect()` helper

At the end of last lesson `store()` finished with `header('Location: /admin/posts')`. The
header has to be written exactly right (`Location`, a colon, a space, then the address), so
a typo there silently breaks the redirect. A tiny helper in `helpers.php` makes sure the
header part is typed only once:

```php
function redirect($to) {
    header("Location: $to");
}
```

The double quotes let `$to` be put straight into the string. In the controller the call is
now just:

```php
redirect('/admin/posts');
```

You can still mistype the address, but then you at least land on a broken page instead of
not being redirected at all.

### 2. 🔎 View: passing the id in the URL and `find()`

To show one post the server has to know **which** post. Every post has a unique primary key,
the `id`, so the button passes it along as a **query parameter**. No form is needed for a
`GET` parameter, it can be written straight into the link:

```php
<a href="/admin/posts/view?id=<?= $post->id ?>" class="btn btn-info">View</a>
<a href="/admin/posts/edit?id=<?= $post->id ?>" class="btn btn-warning">Edit</a>
<a href="/admin/posts/delete?id=<?= $post->id ?>" class="btn btn-danger">Delete</a>
```

There must be no space between `id=` and the `<?=` tag, or the space ends up in the URL.
Hovering a button shows the real address in the bottom left corner of the browser, a quick
way to check that the links came out right (`/admin/posts/view?id=4` and so on).

Loading all posts and searching for the right one would work, but it is wasteful with
thousands of posts. So `DB` got a `find()` that asks the database for one row only:

```php
public function find(string $table, string $class, $id){
    $sql = "SELECT * FROM $table WHERE id=$id";
    $result = $this->conn->query($sql);
    $result->setFetchMode(PDO::FETCH_CLASS, $class);
    return $result->fetch();
}
```

Since `id` is unique, the query finds either one row or none, so instead of `fetchAll()` it
uses **`fetch()`**, which returns the first row (or `false` if there is none). The `Model`
base class wraps it the same way as `all()`:

```php
public static function find($id) {
    $db = new DB();
    return $db->find(static::$table, static::class, $id);
}
```

The controller reads the id from `$_GET` and passes the post to a new view:

```php
public function view() {
    $post = Post::find($_GET['id']);
    view('posts/view', compact('post'));
}
```

`views/posts/view.php` is a vertical table: no header row, one row per field, a `<th>` with
the field's name and a `<td>` with the value (id, title, content, created, updated). The
editor underlines `$post` because it cannot know where the variable comes from (it is
created by `extract()` in the `view()` helper); that warning can be ignored.

### 3. ✏️ Edit: a form that is already filled in

The edit form is a copy of the create form with three changes: the `action` points to
`/admin/posts/edit` with the same `id` parameter, the fields show the current values, and
the button says **Update**:

```php
<form action="/admin/posts/edit?id=<?= $post->id ?>" method="POST">
    <div class="mb-3">
        <label for="title" class="form-label">Title</label>
        <input value="<?= $post->title ?>" name="title" type="text" class="form-control" id="title" placeholder="Some title">
    </div>
    <div class="mb-3">
        <label for="body" class="form-label">Content</label>
        <textarea name="body" class="form-control" id="body" rows="3"><?= $post->body ?></textarea>
    </div>
    <button class="btn btn-primary">Update</button>
</form>
```

An `input` gets its old value through the **`value`** attribute. A `textarea` has no
`value` attribute: its content goes **between the tags**. In both cases there must be no
spaces around the PHP tag. Otherwise every save adds those spaces to the database, the next
edit shows them again and adds more, and the data slowly fills with whitespace.

Showing the form and receiving it again use the same address with different methods:

```php
Route::get('/admin/posts/view', [PostController::class, 'view']);
Route::get('/admin/posts/edit', [PostController::class, 'edit']);
Route::post('/admin/posts/edit', [PostController::class, 'update']);
Route::get('/admin/posts/delete', [PostController::class, 'delete']);
```

### 4. 💾 Update: one `save()` for new and existing models

`update()` finds the post, overwrites its properties with the form data and saves it,
exactly like `store()` but without `new Post()`:

```php
public function update() {
    $post = Post::find($_GET['id']);
    $post->title = $_POST['title'];
    $post->body = $_POST['body'];
    $post->save();
    redirect('/admin/posts');
}
```

But `save()` so far always did an `INSERT`, which would create a copy. How does a model
know whether it is new? By the **id**: a fresh `new Post()` has no id, because the database
hands out ids on insert, while a post loaded with `find()` has one. So `save()` checks it:

```php
public function save() {
    $db = new DB();
    $fields = get_object_vars($this);
    unset($fields['id'], $fields['created_at'], $fields['updated_at']);
    if($this->id) {
        $db->update(static::$table, $fields, $this->id);
    } else {
        $db->insert(static::$table, $fields);
    }
}
```

### 5. 🧩 `DB::update()`: building `SET name='value', ...`

The `UPDATE` syntax is `UPDATE table SET column1='value1', column2='value2' WHERE id=7`.
Unlike `INSERT`, names and values are mixed in pairs, so a single `implode()` is not
enough. A `foreach` over the fields adds one `name='value', ` piece per field (in PHP, `.=`
appends to a string, where most languages would use `+`):

```php
public function update($table, $fields, $id) {
    $updateValuesText = '';
    foreach($fields as $name=>$value) {
        $updateValuesText .= "$name='$value', ";
    }
    $updateValuesText = substr($updateValuesText, 0, -2);
    $sql = "UPDATE $table SET $updateValuesText WHERE id=$id";
    $this->conn->exec($sql);
}
```

Dumping `$sql` before running it showed the problem: the loop also leaves `, ` after the
last field, which breaks the query. **`substr()`** with start `0` and a **negative length
`-2`** keeps everything except the last two characters, so the extra comma and space are
cut off. Dumping the SQL first and only then letting it run is a good habit when building
queries by hand.

### 6. 🗑️ Delete

Delete is the simplest of the four. The model gets a (non static) `delete()` that uses its
own table and id:

```php
public function delete() {
    $db = new DB();
    $db->delete(static::$table, $this->id);
}
```

`DB::delete()` needs no fields at all:

```php
public function delete($table, $id) {
    $sql = "DELETE FROM $table WHERE id=$id";
    $this->conn->exec($sql);
}
```

and the controller finds the post, deletes it and redirects back to the list.

### 7. ⚠️ CRUD, and why not to write this yourself

Create, read, update and delete together are called **CRUD**
(<https://en.wikipedia.org/wiki/Create,_read,_update_and_delete>), the four basic operations
almost every admin panel is made of.

A student asked how to make the hand-built SQL safe. The honest answer: **do not write your
own SQL layer for real projects.** This one only works if every input is well behaved, it is
open to SQL injection and has plenty of bugs; PDO protects against only the worst cases.
Writing it by hand is useful for understanding what a framework does for you, and once
learnphp is finished the class moves on to **Laravel**, which has all of this built in and
secured. Related advice from the lesson: keep PHP on your servers updated, since a serious
zero day in PHP had just been found the week before.

## ✅ Takeaways

1. **A `redirect()` helper** removes the chance of mistyping the `Location` header.
2. **Pass the id as a query parameter** (`?id=4`) in the link and read it from `$_GET`;
   no form is needed for that.
3. **`find()` uses `fetch()`**, not `fetchAll()`: an id matches one row or none.
4. **Prefill an edit form** with `value` on an `input` and with the content between the
   tags of a `textarea`, and never leave spaces around the PHP tag.
5. **One `save()` for both cases**: a model with an id is updated, a model without one is
   inserted.
6. **Build `UPDATE` with a `foreach`** and cut the trailing `, ` with `substr($text, 0, -2)`;
   dump the SQL before running it.
7. **Create, read, update, delete = CRUD.**
8. **Hand-written SQL is for learning only**; real projects use a framework (Laravel is
   next) and keep PHP updated.
